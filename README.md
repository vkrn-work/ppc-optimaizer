# PPC Optimizer

Система автоматизации управления поисковыми рекламными кампаниями в Яндекс Директ для B2B-компании в нише импортного металлопроката.

**Версия:** 1.4.0 · **Деплой:** Railway · **Статус:** Уровни 1–3 в проде и проверены end-to-end на реальном кабинете, включая запись изменений в Яндекс Директ.

|---|---|

| Бэкенд API | https://ppc-optimaizer-production.up.railway.app/docs |

## Что делает система

**Уровень 1 — сбор и аналитика (в проде)**
- Собирает данные из Яндекс Директ API v5 и Яндекс Метрики ежедневно (06:00 МСК)
- Анализирует динамику показателей: позиции, CTR, клики, расход, bounce rate (rule-based движок `cr_analyzer.py`)
- Трекает каждое изменение 7 дней и выдаёт вердикт: подтверждена / отклонена / нейтральная / нет данных
- Поддерживает несколько кабинетов одновременно

**Уровни 2–3 — CRM, ИИ-анализ, запись в кабинет (в проде, проверено на реальных данных)**
- Импорт выгрузки заявок из CRM (CSV/XLSX — 1С, amoCRM, Bitrix24 и т.п.), автоопределение кодировки/разделителя,
  классификация каждой заявки в воронку lead → MQL → SQL по текстовому статусу, матчинг с ключевым словом
  по номеру объявления или по фразе
- ИИ-анализ через выбор одного из 4 LLM-провайдеров: **Claude, Gemini, Groq, OpenRouter**
  (Gemini/Groq/OpenRouter — бесплатные варианты без карты, Claude — платный). Модель получает статистику
  по ключевым словам вместе с воронкой MQL/SQL и приоритезирует изменения по вкладу в SQL, а не в выручку
- Генерация предложений (bid_raise/bid_lower, add_negatives, pause, ad_rewrite, ad_test) с приоритетами
  (Сегодня / Неделя / Месяц) и жёсткими safety-лимитами на сервере: макс. % изменения ставки, потолок ставки,
  дедупликация, и запрет предлагать изменение ставки для кампаний не на ручном управлении (`bid_editable`) —
  для таких кампаний модель вместо этого предлагает минус-слова, паузу или правки объявления
- Approve/reject предложений и запись подтверждённых изменений напрямую в Яндекс Директ API v5
  (ставки через `keywords.update`, минус-слова через `adgroups.update` со слиянием с текущим списком,
  пауза ключей через `keywords.suspend`) — подтверждено реальным ответом API и проверено в кабинете Директа

**Известное ограничение (не баг):** ставка ключевого слова редактируется через API только для кампаний
на стратегии `MANUAL_CPC`. Для кампаний на автостратегиях/ЕПК Yandex Direct API не принимает поле `Bid`
на уровне ключевого слова — это ограничение самого API, а не системы. Для таких кампаний ИИ намеренно
не предлагает изменение ставки (см. `docs/CHANGELOG.md`, версия 1.4.0).

## Быстрый старт (локальная разработка)

```bash
git clone https://github.com/vkrn-work/ppc-optimaizer
cd ppc-optimaizer
docker-compose up -d

# Фронтенд: http://localhost:3000
# API docs: http://localhost:8000/docs
```

Чтобы протестировать ИИ-анализ локально — добавьте хотя бы один ключ в `.env`
(`GEMINI_API_KEY` или `GROQ_API_KEY` — бесплатно, без карты). Подробнее — в
[docs/PROJECT_DOCUMENTATION.md](docs/PROJECT_DOCUMENTATION.md), раздел «Локальная разработка».

## Стек

| Компонент | Технология |
|---|---|
| Фронтенд | Next.js 14 + React 18 |
| Бэкенд | FastAPI + Python 3.12 |
| БД | PostgreSQL + SQLAlchemy async |
| Очереди | Celery + Redis |
| ИИ-анализ | Claude (Anthropic) / Gemini / Groq / OpenRouter — выбор провайдера на фронте |
| Деплой | Railway (3 сервиса: backend, worker, frontend + Postgres + Redis) |
